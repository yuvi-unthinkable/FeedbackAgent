# PLAN.md — Real-Time Medical Consultation Voice Agent (Vapi-Inspired Architecture)

## 1. Project Overview & Objective
Build a full-stack, real-time speech-to-speech outbound medical calling system and doctor dashboard using React, Node.js, and free-tier AI models.
- **Workflow:**
  1. Doctor selects a patient on the React Dashboard and clicks **"Start Consultation Call"**.
  2. Node.js backend fetches the patient's consultation context, required questions, and approved guidance from Supabase.
  3. Twilio dials the patient's phone, records the dual-channel call audio, and opens a bidirectional WebSocket (`<Connect><Stream>`) to our Node.js server.
  4. Node.js bridges Twilio's 8kHz mu-law audio stream with the **Google Gemini Live API** (`models/gemini-3.8-live`) for sub-second native speech-to-speech dialogue and instant barge-in handling.
  5. During the call, live telemetry (`speech-update`, `transcript`) streams to the React Dashboard over WebSockets.
  6. Upon hangup, an asynchronous worker (`reportWorker.js`) sends the transcript to **Groq (`llama-3.3-70b-versatile`)** or **Gemini 3.8 Flash** to extract a structured clinical JSON report and saves it alongside the Twilio recording URL.

## 3. Implementation Phases

### Phase 1: REA Static Inspection (`./vapi-target`)
- Initialize `./vapi-target` and install `@vapi-ai/web` (`npm init -y && npm install @vapi-ai/web`).
- Perform static JavaScript inspection on `./vapi-target/node_modules/@vapi-ai/web`.
- Trace `Vapi` class initialization, its `EventEmitter` event names, and payload structures:
  - `call-start` / `call-end`
  - `speech-update` (`{ status: "started" | "stopped", role: "assistant" | "user" }`)
  - `transcript` (`{ role, transcriptType: "partial" | "final", transcript }`)
  - `function-call` and `error`
- Write the extracted schemas and state transition notes to `./backend/src/vapi-schemas.json`.

### Phase 2: Audio Resampling & Utility Layer (`./backend/src/audioUtils.js`)
- Implement zero-dependency or lightweight buffer utilities in `audioUtils.js`:
  - `mulawToPcm16(base64Mulaw)`: Decodes base64 8kHz G.711 mu-law bytes from Twilio into 16-bit Linear PCM and upsamples from 8kHz to 16kHz (base64 encoded) for Gemini Live input.
  - `pcm24ToMulaw(base64Pcm24)`: Downsamples 24kHz 16-bit Linear PCM audio returned by Gemini Live down to 8kHz and encodes into G.711 mu-law base64 payloads for Twilio playback.
- Include a unit test script (`./backend/test/audioUtils.test.js`) to verify round-trip buffer lengths and sample rates.

### Phase 3: Vapi-Style CallSession Orchestrator (`./backend/src/CallSession.js`)
- Build `CallSession` extending Node's `EventEmitter`:
  - **Session Setup**:
    - Connect to `wss://generativelanguage.googleapis.com/ws/google.ai.generativelanguage.v1beta.GenerativeService.BidiGenerateContent?key=${process.env.GEMINI_API_KEY}`.
    - On socket open, send setup frame using `models/gemini-3.8-live` (or `models/gemini-2.0-flash-exp` fallback), `responseModalities: ["AUDIO"]`, and dynamic `systemInstruction` populated with patient name, age, consultation context, questions to ask, and allowed guidance.
  - **Twilio -> Gemini Audio Relay**:
    - Listen for Twilio media events, convert `msg.media.payload` via `mulawToPcm16()`, and send via `realtimeInput.mediaChunks` (`audio/pcm;rate=16000`).
  - **Gemini -> Twilio Audio Relay & Instant Barge-In**:
    - Listen for `serverContent` from Gemini Live.
    - **Barge-In Rule**: If `response.serverContent?.interrupted === true`, immediately send `{ event: "clear", streamSid: this.streamSid }` to the Twilio WebSocket to flush queued outbound audio in <50ms, and emit `speech-update` (`{ role: "user", status: "started" }`) to the React dashboard.
    - **Audio Output**: Convert `inlineData.data` via `pcm24ToMulaw()` and send `{ event: "media", streamSid, media: { payload } }` to Twilio.
    - **Transcripts**: Append any text parts or input transcriptions to `this.transcript` and broadcast `{ type: "transcript", role, text, timestamp }` to connected React clients.
  - **Teardown & Report Trigger**:
    - When Twilio sends `{ event: "stop" }`, close the Gemini WebSocket, invoke `generateMedicalReport(this.patient, this.transcript)`, save resulting JSON to Supabase (or local fallback store), and broadcast `{ type: "end-of-call-report", patientId, report }` to the React dashboard.

### Phase 4: Express API, Webhooks & Post-Call Worker (`./backend/src/server.js`, `twilioClient.js`, `reportWorker.js`)
- **REST Endpoints (`server.js`)**:
  - `GET /api/patients`: Returns patient list with seed mock data (strictly fictional patient profiles for HIPAA-safe development).
  - `POST /api/calls/outbound`: Accepts `{ patientId }`, creates a `call_reports` record, and triggers `startPatientCall()` in `twilioClient.js` (or starts a local simulated call session if `?simulate=true` is passed for browser testing without spending Twilio credits).
  - `POST /api/webhooks/recording-ready`: Twilio webhook callback that receives `RecordingUrl` and updates corresponding `call_reports` row.
  - `GET /api/reports/:patientId`: Returns past consultation reports and recording URLs for a patient.
- **Post-Call Worker (`reportWorker.js`)**:
  - Calls Groq (`llama-3.3-70b-versatile`) or Gemini 3.8 Flash with `response_format: { type: "json_object" }`.
  - Enforces output schema:
    ```json
    {
      "clinicalSummary": "string",
      "urgencyLevel": "LOW | MEDIUM | HIGH",
      "symptomsReported": ["string"],
      "questionResponses": [{ "question": "string", "patientAnswer": "string" }],
      "guidanceDelivered": ["string"],
      "followUpRequired": true
    }
    ```

### Phase 5: React Medical Dashboard (`./frontend`)
- Scaffold a clean, responsive medical dashboard in React + Vite:
  - `useCallSocket.js`: Connects to `ws://localhost:4000/dashboard-events`, maintaining live state for `callStatus`, `activeSpeaker` (`user | assistant | idle`), `liveTranscript[]`, and `latestReport`.
  - `PatientQueue.jsx`: Displays seeded mock patients, their consultation reason, required questions, a "Call Patient (Twilio)" button, and a "Simulate Call (Local Test)" button.
  - `LiveCallMonitor.jsx`: Displays a visual pulse indicator for active speaker (`speech-update`), a "Barge-In Detected" badge when interrupts occur, and a real-time auto-scrolling transcript feed.
  - `ConsultationReportModal.jsx`: Displays the completed post-call report:
    - Color-coded `urgencyLevel` badge (HIGH = Red, MEDIUM = Amber, LOW = Emerald).
    - Clinical summary and symptoms list.
    - Structured Q&A table mapping required consultation questions to patient answers.
    - HTML5 `<audio controls>` player bound to `recording_url`.
